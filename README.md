# SimpleFS — A Minimal File System in C

**CSE 321: Operating Systems | Term Lab Project**

![C](https://img.shields.io/badge/Language-C11-blue)
![Platform](https://img.shields.io/badge/Platform-Linux%20%7C%20WSL-lightgrey)

A hand-built, flat file system written in C that formats a raw binary disk image and stores real files inside it — no OS file-system calls involved. The project implements two command-line tools: **`simplefs_builder`** (formats the image) and **`simplefs_adder`** (copies host files into the image).

| Block size | 4 096 bytes |
| Total blocks | 64 |
| Max inodes | 32 |
| Max file size | 12 288 bytes (3 direct blocks) |
| Directory support | Single-level (flat root directory only) |

SimpleFS is intentionally minimal: one directory (root), no subdirectories, no symbolic links, and no journaling. Its purpose is to make every layer of a real file system tangible and inspectable with a hex editor.

## File System Layout

The 256 KiB disk image is divided into fixed-purpose blocks:

| Block # | Purpose |
|---|---|
| 0 | **Superblock** — magic number, geometry, region offsets |
| 1 | **Inode bitmap** — 1 bit per inode slot (32 bits used) |
| 2 | **Data bitmap** — 1 bit per data block (60 bits used) |
| 3 | **Inode table** — 32 × 128-byte inode records |
| 4 – 63 | **Data region** — 60 blocks of 4 096 bytes each |


![SimpleFS disk layout](<file system.jfif>)

Block 4 is permanently reserved as the root directory's data block.

## Key Data Structures

All structures are defined in [`simplefs.h`](simplefs.h).

### `superblock_t`
Stored at Block 0. Records the disk layout so any tool can open the image without hard-coded assumptions.

```c
typedef struct {
    uint32_t magic;              // 0x53465331 — identifies a valid SimpleFS image
    uint32_t block_size;         // 4096
    uint32_t total_blocks;       // 64
    uint32_t inode_count;        // 32
    uint32_t inode_bitmap_block; // 1
    uint32_t data_bitmap_block;  // 2
    uint32_t inode_table_block;  // 3
    uint32_t data_region_block;  // 4
    uint32_t root_inode;         // 1
} superblock_t;
```

### `inode_t`
128 bytes per inode. Stores file metadata and up to 3 direct block pointers.

```c
typedef struct {
    uint16_t type;           // TYPE_FILE (1) or TYPE_DIRECTORY (2)
    uint16_t links;          // hard-link count
    uint32_t size;           // file size in bytes
    uint32_t direct[3];      // absolute block numbers (0 = unused)
    uint8_t  reserved[108];  // padding to 128 bytes
} inode_t;
```

### `dirent_t`
64 bytes per directory entry. Each occupied slot in the root data block is one of these.

```c
typedef struct {
    uint32_t inode_no;  // 0 = free slot
    uint8_t  type;      // TYPE_FILE or TYPE_DIRECTORY
    char     name[59];  // null-terminated filename
} dirent_t;
```

## Tools

### `simplefs_builder`
Formats a fresh disk image:
1. Zeroes all 64 blocks.
2. Writes the superblock (Block 0).
3. Marks inode 1 allocated in the inode bitmap (Block 1).
4. Marks data block 4 allocated in the data bitmap (Block 2).
5. Initializes the root directory inode (inode 1, Block 3).
6. Writes `.` and `..` directory entries into Block 4.

### `simplefs_adder`
Copies a host file into the image:
1. Validates the image (magic number check).
2. Checks file size ≤ 12 288 bytes.
3. Checks for duplicate filename in root directory.
4. Allocates a free inode and the required data blocks (first-fit).
5. Copies file content into allocated blocks (zero-padded to block boundary).
6. Writes the new inode and directory entry, updates bitmaps and root inode size.

## Build

Compile each tool separately with GCC (C11, all warnings enabled):

```bash
gcc -Wall -Wextra -std=c11 simplefs_builder.c -o simplefs_builder
gcc -Wall -Wextra -std=c11 simplefs_adder.c   -o simplefs_adder
```

No external libraries are required — only the C standard library.

## Usage

### 1. Format a new disk image

```bash
./simplefs_builder --image disk.img
# SimpleFS image created successfully: disk.img
```

### 2. Add files to the image

```bash
./simplefs_adder --input disk.img --file test1.txt
./simplefs_adder --input disk.img --file test2.txt
./simplefs_adder --input disk.img --file test3.txt
```

### 3. Inspect the image (optional)

```bash
xxd disk.img | less          # hex dump
hexdump -C disk.img | less   # alternative
```

Block 0 (offset 0x0000) should start with the magic number `31 53 46 53` (little-endian `0x53465331`).

## Implementation Details

### Bitmap helpers

```c
void set_bit(unsigned char *bitmap, int index);   // mark index as used
int  is_bit_set(unsigned char *bitmap, int index); // test if index is used
```

Bits are packed 8-per-byte. Inode bitmap index `i` corresponds to inode number `i + 1`. Data bitmap index `i` corresponds to absolute block number `i + DATA_REGION_BLOCK` (i.e., `i + 4`).

### Inode numbering

Inode numbers start at **1** (inode 0 is reserved/invalid). The inode table starts at Block 3; inode `n` lives at byte offset:

```
INODE_TABLE_BLOCK * BLOCK_SIZE + (n - 1) * sizeof(inode_t)
```

### Mask preprocessing (binary mask for segmentation)

The root directory entry at index 0 is always `.` (self) and index 1 is always `..` (parent). Both map to inode 1. `simplefs_adder` begins its free-slot search at index 2.

### Multi-block files

Files up to 12 288 bytes span up to 3 direct blocks. Required block count:

```c
required_blocks = (file_size + BLOCK_SIZE - 1) / BLOCK_SIZE;
// zero-byte files require 0 blocks
```

Each block is allocated first-fit from the data bitmap, written with the source content (zero-padded), and recorded in `inode.direct[0..2]`.

## Constraints

| Constraint | Value |
|---|---|
| Maximum file size | 12 288 bytes (3 × 4 096) |
| Maximum files in root | 62 (64 slots − `.` − `..`) |
| Maximum inodes | 32 (inode 1 = root, 2–32 = files) |
| Subdirectories | Not supported |
| Filenames | Up to 58 characters + null terminator |
| Image size | Exactly 262 144 bytes (256 KiB) |
